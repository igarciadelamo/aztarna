# Aztarna — Backend

Lightweight stateless REST API (`GET /v1/sky-forecast`) in **Python (FastAPI + Skyfield)**. See
[`../PRODUCT.md`](../PRODUCT.md) for the API contract, the thin-client principle and privacy rules.

## Documentation

- [`docs/data-pipeline-and-sources.md`](docs/data-pipeline-and-sources.md) — external data sources,
  rate limits, fallback behavior and the canonical `NormalizedSkyEvent` format.

## Setup

### Tooling: uv
- The project is managed with [uv](https://github.com/astral-sh/uv) (Astral, actively maintained).
- `pyproject.toml` and `uv.lock` are committed. `.python-version` pins Python 3.13.
- Runtime dependencies: `fastapi`, `uvicorn`, `skyfield`. HTTP calls (CelesTrak, Open-Meteo) use the stdlib `urllib`.
- Dev dependencies (`uv add --dev`): `pytest`, `ruff`, `httpx2`, `pre-commit`.

| Task | Command |
|---|---|
| Install deps, ephemeris + git pre-commit hook | `make setup` (needs uv: `brew install uv`) |
| Run locally (dev console http://127.0.0.1:8000/dev, API docs `/docs`) | `make run` |
| Test | `make test` |
| Lint / format check | `make lint` |
| Auto-fix lint + format | `make format` |
| Build and run the Docker image | `make docker` |
| English Android strings for tip codes | `make tips-strings` (see `android/README.md`) |

**Pre-commit hook** (`.pre-commit-config.yaml` at the repo root, installed by `make setup`): on each
commit that touches `backend/`, it runs `ruff check --fix`, `ruff format` and `pytest`. If a hook
changes files, the commit stops; review the changes, `git add` them and commit again. The tools run
from `backend/uv.lock`, so their versions match `make lint`.

### Routes

| Route | Purpose |
|---|---|
| `GET /v1/sky-forecast?lat=&lon=` | The only product endpoint (`PRODUCT.md` §5). `400` on invalid coordinates. |
| `GET /v1/app-version?version_code=` | Update gate: returns `min_version_code`, `latest_version_code` and `action` (`FORCE_UPDATE` / `SUGGEST_UPDATE` / `NONE`). See `PRODUCT.md` §5. |
| `GET /health` | Always `200` while serving. Returns `{"status": "ok" \| "degraded", "tle_age_hours", "weather_budget_left"}`. `degraded` means no CelesTrak download for 48 h or this hour's weather budget is spent; point an uptime monitor's keyword alert at it. |
| `GET /dev` | **Local only** (`AZTARNA_DEV_UI=1`, set by `make run`; off in Docker): a plain HTML console (`aztarna/dev.html`). Search a place by name (Open-Meteo geocoding, called from the browser), use your location, or type lat/lon. It shows tonight's summary, an events table (times in local time, geometry, weather, verdict, alert times, tips), health and the raw JSON. `?lat=&lon=` in the URL is kept, so views can be reloaded and shared. |
| `GET /docs`, `GET /openapi.json` | Generated by FastAPI: the API contract, always in sync with the code. |

No other routes are planned.

### Event Sources (calculation abstraction)
Every calculation backend implements one interface (`aztarna/sources/__init__.py`):

```python
class EventSource(Protocol):
    def events(self, lat, lon, start, end) -> list[NormalizedSkyEvent]: ...
```

To add a backend (Skyfield, the static shower table, a future library or API), implement `events()`
and append an instance to `SOURCES`. The pipeline (`forecast.py`) merges all sources and sorts them
by time. If a source raises, only that source's events are dropped, never the whole response.

**Registered sources:** `SkySource`, `SatelliteSource`, `MeteorSource`. Tests in
`tests/test_sources.py` check them against published facts (eclipse times, opposition dates, moon
phase at meteor peaks) and run offline: `tests/conftest.py` blocks network access, and satellites
use a fixture TLE.

**Known simplifications** (marked `ponytail:` in the code):
- Meteor peaks use a fixed calendar date (±1 day).
- Satellite brightness uses a diffuse-sphere model (±1 mag).
- Eclipse partial-phase length assumes a constant Moon speed (a few minutes off).
- Best viewing time is sampled every 10 minutes.
- Polar night (Sun never above −6°) yields no night-based events.

### State (the service is stateless per request, but not per process)
- **TLE file:** `$DATA_DIR/stations.tle` (Docker volume), so a container restart does not refetch it
  and risk a CelesTrak IP block. It is refreshed at startup and on request when older than 24 h. A
  failed fetch keeps the old file and is retried at most hourly. Orbit data older than 7 days yields no
  satellite events.
- **Weather cache:** an in-memory dict keyed by rounded coordinates, with a TTL. It holds no other
  user data.
  This is a per-process cache, so it only works with a single worker and a single instance. Move it
  to Redis if we ever scale out.
- **Weather budget:** at most 300 Open-Meteo calls per hour (`MAX_FETCHES_PER_HOUR` in
  `weather.py`), about 7,200 a day against the free tier's 10,000. Over budget, the server serves
  cached weather or `WEATHER_UNKNOWN`, never "clear". This stops one client cycling through
  coordinates from exhausting the quota for everyone, without tracking IPs.
- **Ephemeris:** `de421.bsp` is downloaded at image build time and baked into the image, so nothing
  is fetched at runtime.

### Configuration (environment variables)

| Variable | Default | Purpose |
|---|---|---|
| `MIN_VERSION_CODE` | `1` | Lowest app `versionCode` allowed; anything older gets `FORCE_UPDATE`. |
| `LATEST_VERSION_CODE` | `1` | Newest published `versionCode`; anything older gets `SUGGEST_UPDATE`. Bump it after each Play release. |
| `DATA_DIR` | `data` locally, `/data` in Docker | Location of the TLE file (`backend/data/` locally, git-ignored). |

### Docker
A single image built from a multi-stage `Dockerfile`:
1. **Build stage:** `python:3.13-slim`, with the uv binary copied from `ghcr.io/astral-sh/uv:0.13.9`.
   It runs `uv sync --locked --no-dev` (and will download `de421.bsp` once Skyfield lands).
2. **Runtime stage:** `python:3.13-slim` with only `.venv` and the code. Runs as a
   non-root user, exposes port `8000`, and has a `HEALTHCHECK` on `/health`.
3. **Command:** `uvicorn aztarna.main:app --host 0.0.0.0 --port 8000 --no-access-log`.
   `--no-access-log` enforces the privacy rule that no IP logs are kept (`PRODUCT.md` §3).

```
make docker   # = docker build -t aztarna-backend . && docker run --rm -p 8000:8000 -v aztarna-data:/data aztarna-backend
```

There is no `compose.yaml`: it is a single service with one volume, so `docker run` covers it. Add
Compose when a second service (e.g. Redis) appears.

### CI (`.github/workflows/backend.yml`)
Runs on PRs and pushes to `main` that touch `backend/`:
1. **test:** `uv sync --locked`, ephemeris (cached), `make lint`, `make test`.
2. **image:** builds the Docker image. On `main` it also pushes
   `ghcr.io/igarciadelamo/aztarna-backend:latest` and `:<sha>`. There is no deploy step yet.

### Release Checklist
**Backend release** (once deploy exists, this is: merge to `main`, pull and restart on the VM):
- [ ] CI is green on `main` and the image has been pushed to GHCR.
- [ ] On the VM: `docker pull` the new tag and restart with the `/data` volume and the env vars below.
- [ ] Reverse proxy has access logs **off** (privacy rule). The container already runs with `--no-access-log`.
- [ ] `curl https://<host>/health` returns `"status": "ok"` within a few minutes (TLE downloaded).
- [ ] Uptime monitor: keyword alert on `"degraded"` at `/health`.

**Android release:**
- [ ] After the new version is live on Play, bump `LATEST_VERSION_CODE` on the server (users get `SUGGEST_UPDATE`).
- [ ] Only if older versions break against the API: bump `MIN_VERSION_CODE` (users get `FORCE_UPDATE`).

A small script on the VM could do these bumps over SSH (edit the env file, restart the container);
add it when we release often enough to need it.

**Yearly:**
- [ ] Update `aztarna/data/meteor_showers.json` from the new IMO calendar PDF (dates, ZHR).
- [ ] Before the next release that touches satellites, re-check magnitudes against Heavens-Above.
  If they've drifted, refit `TRACKED` in `sources/satellites.py` and update the test reference.

**App (one-off):**
- [ ] About screen shows "Weather data by Open-Meteo.com" (CC BY 4.0 requirement).
